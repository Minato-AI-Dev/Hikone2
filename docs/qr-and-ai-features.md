# Hikone2：QR・AI相談の利用範囲

## QRコードリーダー

- ホーム画面の「QRコードを読み取る」でスマートフォンのカメラを開き、QR内の文字列を表示できます。
- 読み取ったURLを自動で開きません。未知のURLを意図せず訪問するリスクを避けます。
- 訪問中の「現地QRを読み取る（試験用）」は、その体験に対応するコードとの一致を確認します。認めるコード形式は `hikone://checkin/<ACTION_ID>` か `https://hikone2.vercel.app/?checkin=<ACTION_ID>` のみです。
- 体験コードは公開識別子であり、同じ文字列を第三者が生成できます。QRの一致は**現地到着・体験完了の証明ではありません**。訪問履歴は「行ってきた」を押した本人の申告です。
- **現地にはまだQRがありません。** 設置先の許諾と現地の表示試験が済むまで実際の現地チェックインとは呼びません。必要なら端末で文字列を手入力して、試験できます。
- 不正チェックインを防ぐには、現地設置、サーバー側署名または定期更新トークン、配布・管理ルール、実証先の同意が追加で必要です。

## AI相談

- ホーム画面の「AIに相談する」で自由文章を受け付けます。
- `OPENAI_API_KEY` と `OPENAI_MODEL` がHikone2の**サーバー環境**に設定され、利用制限用Redisが使えるときのみクラウドAIを使用します。
- 未接続・API失敗時は端末内キーワード解析に切り替え、推薦結果の画面でその旨を表示します。この処理を「クラウドAI」とは表記しません。
- AIが観光地や徒歩分数を独自に追加することはありません。最終候補は位置・営業時間・最低滞在条件・経路の充足を判定する推薦ロジックで制限します。
- OpenAIのAPIキーはチャット、GitHub、`VITE_` 環境変数に登録しないでください。

## Google Routes / Google Places

- Routes APIはサーバー側 `GOOGLE_MAPS_API_KEY` を使って、ユーザーが選択した登録済み地点間の徒歩移動時間を照会します。
- Places API (New)は同じAPIキーに権限がなければ使えません。店舗のPlace IDは個別に住所と照合しなければ登録できません。
- 公開・推薦のためには、代表ルートの実地歩行、入口の検証、店舗への確認が必要です。

## テスト

`npm ci && npm test && npm run build && npm run typecheck:api` のほか、GitHub ActionsのMobile browser smoke とlive API isolation smokeを実行します。QRのカメラ起動は**物理端末のiOS SafariとAndroid Chrome**で別途試験してください。
